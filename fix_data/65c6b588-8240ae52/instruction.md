The Python SDK for Claude (`claude_agent_sdk`) persists conversation transcripts only to the local `~/.claude/projects` directory as JSONL files. Applications that run the SDK in ephemeral or multi-tenant environments (containers, serverless functions, horizontally scaled workers) have no supported way to store, list, resume, or fork sessions from a durable backend such as a database or object store — the TypeScript SDK already exposes a pluggable session-store adapter for exactly this, and the Python SDK is missing it. Your job is to bring the Python SDK to parity by adding a pluggable `SessionStore` adapter surface: a protocol that a third party can implement, a write path that mirrors live transcripts into the store, a read path that lets the CLI resume a session that exists only in the store, and a set of store-backed session-management helpers. Existing on-disk behavior and the nine synchronous session helpers must keep working unchanged; the new store-backed capabilities are additive async siblings.

When an application supplies a session store through the new `session_store` field on `ClaudeAgentOptions`, the SDK should treat it as the source of truth for transcripts. A store is any object that satisfies the `SessionStore` protocol, importable as `from claude_agent_sdk import SessionStore`. It is a `typing.Protocol` with two required async methods — `append(key, entries)` and `load(key)` — and three optional async methods — `list_sessions(project_key)`, `delete(key)`, and `list_subkeys(key)`. `append` takes a `SessionKey` and a `list[SessionStoreEntry]` and returns `None`; `load` takes a `SessionKey` and returns `list[SessionStoreEntry] | None` (`None` meaning "no such session"). Probing for an optional method (for example, whether a given store implements `list_sessions`) must be possible at runtime. The supporting types are `SessionKey` (a `TypedDict` with `project_key: str`, `session_id: str`, and an optional `subpath`), `SessionStoreEntry` (a `total=False` `TypedDict` whose `type` field is required and which passes any extra keys through untouched, e.g. `uuid`, `timestamp`), `SessionStoreListEntry` (`session_id: str`, `mtime: int`), and `SessionListSubkeysKey` (`project_key: str`, `session_id: str`). All must be importable from the top-level `claude_agent_sdk` package, and `SessionKey`/`SessionStore`/`SessionStoreEntry` must also be importable from `claude_agent_sdk.types`.

Ship a reference `InMemorySessionStore` (importable from `claude_agent_sdk`) that implements all five methods correctly and additionally provides test conveniences: a `get_entries()` accessor, a `.size` property that counts only main-session transcripts (not subagent subkeys), and a `clear()` method. Its `load` must hand back a fresh list each time, so that a caller appending to, removing from or reordering the returned list cannot change what the store holds. `ClaudeAgentOptions` gains two new fields: `session_store: SessionStore | None = None` and `load_timeout_ms: int = 60_000`.

Provide `project_key_for_directory(directory=None)`, importable from `claude_agent_sdk`, which derives a stable, filesystem-safe project key string from a directory. It defaults to the current working directory when `directory` is `None`. The key it returns must be the same key the CLI subprocess derives for that directory, so that a store lookup cannot silently miss. Any two spellings that name the same directory must collapse to a single key, including the same directory name written with different Unicode normalisations. Directories whose paths are too long to be used verbatim must still yield a deterministic, filesystem-safe key that the parent process and the subprocess both derive identically. The key must be deterministic: the same path always produces the same key across calls.

**Write path.** While a conversation runs with a store configured, the transcript the CLI is writing must also be reaching the store, and the application must be unaware of it: the mirroring traffic must never surface as ordinary messages in the message stream a caller iterates. When no store is configured, the SDK must not ask the CLI for that traffic at all, and any mirroring data that does arrive must be discarded rather than stored or yielded.

Delivery to the adapter is buffered, and the buffering has a contract the adapter can rely on. Enqueuing entries must not by itself contact the store, so nothing reaches an adapter until a flush happens. A flush must have delivered every entry enqueued so far by the time it returns. Entries belonging to one transcript arrive as a single `append` in enqueue order; entries belonging to different transcripts arrive as separate `append` calls, each under its own session key; and an empty batch produces no `append` at all — adapters must never see a phantom key with no entries. A backlog must not grow without bound: delivery must begin without waiting for an explicit flush once the backlog exceeds 500 buffered entries or 1 MiB. Whatever the interleaving of those size-triggered deliveries and explicit flushes, every entry must reach the adapter exactly once and in order — never duplicated, never reordered, never lost. Everything pending must have reached the store before a result message is surfaced to the application; mirroring data that arrives after the result must still reach the store by the time the session closes; and closing delivers anything still outstanding.

A store is third-party code and may fail. If `append` raises or exceeds its time budget, the mirror must not propagate the failure into the conversation: the mirror must absorb the failure and keep running; its delivery path must never raise into the conversation. The caller must still learn that persistence failed rather than silently losing data, so a failed append surfaces a `MirrorErrorMessage` (a `SystemMessage` subclass with `subtype="mirror_error"`, a `key: SessionKey | None`, and an `error: str`) into the message stream instead of dropping the data or crashing it.

Transcript file paths must be mappable back to store keys. A main transcript maps to its project key and session id. A subagent transcript is one nested inside that session's own directory; it maps to the same pair plus a `subpath` that identifies the agent within that session, expressed with forward slashes regardless of OS and without the file extension. A transcript sitting directly in the project directory is a main transcript and one nested below the session directory is a subagent transcript; nothing else is a transcript. The on-disk layout these paths follow is the one the repository already reads elsewhere. Any path that does not unambiguously match a known transcript shape returns `None` instead of a partial or guessed key, and no input may make the function raise — a path that cannot be expressed relative to the projects directory is simply unmappable. A trailing path separator on the configured directory must not change the derived key. The projects directory the mirror writes under must honor a `CLAUDE_CONFIG_DIR` override supplied through `options.env` in preference to the ambient process environment, and must ignore an empty-string override.

**Read path.** The CLI can only resume a session it can read from disk, so a session that lives only in the store must be staged for it. Staging must be disposable and strictly session-scoped, must leave the caller's real configuration untouched, and must round-trip: what the CLI reads back has to reparse to exactly the entries the store returned. Authentication must keep working across the staged configuration: whatever credentials the caller's environment actually holds must be found and made available there, in a form that still authenticates but does not carry long-lived renewal secrets into the staging area. A session's subagent transcripts are part of the session and must be resumable with it, staged in the layout the CLI reads: each subagent's transcript as a `.jsonl` file, with its agent-metadata entry written alongside as a `.meta.json` sidecar under the same name. Session ids and subpaths arrive from the store and are therefore untrusted input: they must be validated so that nothing can ever be written outside the staging area, and a value that fails validation must be rejected rather than sanitized into something writable.

Staging costs a store round-trip and leaves credentials on disk for the lifetime of the session, so it must be skipped entirely — nothing read from the store, nothing written to disk — whenever it cannot produce something a CLI subprocess will actually read: when the request does not identify a resumable session, when the store has nothing to return for it, and when no CLI subprocess will be spawned at all. For a "continue" (rather than an explicit resume id), the SDK resumes the most recently active session that is a real conversation rather than a sidechain; when the project holds nothing but sidechains there is nothing to resume. The choice must be deterministic for any given set of stored sessions.

When staging succeeds, the CLI must be pointed at the staged configuration through `CLAUDE_CONFIG_DIR`, invoked with `--resume`, and must not also receive `--continue`; the mirror must write under the staged configuration rather than the caller's. The staged directory must always be cleaned up — on normal disconnect and on every path that fails before or during spawn: a direct connect failure, an `async with` (`__aenter__`) failure, a failure during query initialization, a cancellation before spawn, and a one-shot query whose transport fails or whose consumer breaks early. Where a subprocess or transport was already created, it must be closed before the staged directory is removed. Cleanup must survive a filesystem that refuses the first removal attempt for transient reasons rather than leaking the directory, and must still run when the failure arrives as a cancellation, or after staging has already begun creating directories.

The `load_timeout_ms` option bounds every store read during resume: a slow `load`, `list_sessions`, or `list_subkeys` must raise when it exceeds the timeout, and a timeout while enumerating subagents must still clean up the staged directory. An exception raised inside `load` must be wrapped and surfaced clearly, and an entry that is not JSON-serializable must surface a clear error rather than a cryptic one.

**Store-backed helpers.** Add nine store-backed session helpers as async siblings of the existing sync helpers (which must keep their exact signatures). Each takes a `session_store` first argument and an optional `directory`: `list_sessions_from_store(session_store, directory=None, limit=None, offset=0)`, `get_session_info_from_store(session_store, session_id, directory=None)`, `get_session_messages_from_store(session_store, session_id, directory=None, limit=None, offset=0)`, `list_subagents_from_store(session_store, session_id, directory=None)`, `get_subagent_messages_from_store(session_store, session_id, agent_id, directory=None, limit=None, offset=0)`, `rename_session_via_store(session_store, session_id, title, directory=None)`, `tag_session_via_store(session_store, session_id, tag, directory=None)`, `delete_session_via_store(session_store, session_id, directory=None)`, and `fork_session_via_store(session_store, session_id, directory=None, up_to_message_id=None, title=None)`.

Required behaviors: `list_sessions_from_store` returns sessions most-recently-active first, drops sidechain sessions, applies `limit`/`offset` to what remains after that filter, does not mutate the list the adapter returned, keeps listing the rest when one row's `load` errors instead of failing the whole listing, and does not issue unbounded concurrent loads against the adapter; it raises when the store does not implement `list_sessions`. `get_session_info_from_store` returns `None` for an unknown session, reflects a session's custom title, and falls back to the given directory for `cwd` when entries lack one. `get_session_messages_from_store` returns the message chain in order, ignores metadata (non-message) entries, and honors `limit`/`offset`. The subagent helpers report one entry per agent even when that agent appears under several subpaths, support nested subpaths, exclude agent-metadata entries from returned messages, report nothing for a session id that is not a valid UUID rather than treating it as a lookup, and refuse to enumerate when the store lacks `list_subkeys` — except a direct-path subagent fetch, which must work without it. `rename_session_via_store` gives the session a custom title; `tag_session_via_store` sets a tag, clears it when passed `None`, has the tag reflected in session info, and works against an adapter that round-trips entries with their keys reordered. `delete_session_via_store` removes the session, is a no-op when the store lacks `delete`, and rejects a non-UUID session id. `fork_session_via_store` produces a new, independent session: it returns a fresh session id, and the fork's message chain must stand on its own rather than sharing message identity with the original, so that neither session's later history can be confused with the other's. When `up_to_message_id` is given the fork ends at that message. The fork must carry a meaningful title derived from the original rather than an empty one, and any entry it synthesizes must be as well-formed as the entries it copies. It rejects a non-UUID `session_id` or `up_to_message_id`.

Session-store options must be validated before a connection is attempted: no store is always valid; a valid store passes; requesting continue-conversation with a store that lacks `list_sessions` must raise, while a store that implements `list_sessions` is accepted; when an explicit resume ID is also provided alongside continue-conversation, the explicit resume wins and `list_sessions` is provably never called — that combination is accepted even if the store lacks `list_sessions`; a session store must not be combined with file-based checkpointing.

Finally, publish a `run_session_store_conformance(make_store, *, skip_optional=frozenset())` coroutine under `claude_agent_sdk.testing` (a package, importable as `from claude_agent_sdk.testing import run_session_store_conformance`) so third-party adapter authors can validate their implementations without a pytest dependency. It accepts either a sync or async store factory, runs a suite of behavioral contracts against the produced store, auto-skips contracts for optional methods the store does not implement, lets the caller suppress specific contracts via `skip_optional`, and passes cleanly against `InMemorySessionStore`.

Do not modify any test files.

**Published surface.** These are the names callers and adapter authors depend on, and the protocol tokens the CLI already defines. How you decompose the implementation behind them — modules, classes, helpers, constants — is yours to decide.

- Public exports from `claude_agent_sdk`: `SessionStore`, `InMemorySessionStore`, `SessionKey`, `SessionStoreEntry`, `SessionStoreListEntry`, `SessionListSubkeysKey`, `MirrorErrorMessage`, `project_key_for_directory`, `ClaudeAgentOptions`, and the nine `*_from_store`/`*_via_store` async helpers named above.
- From `claude_agent_sdk.types`: `SessionKey`, `SessionStore`, `SessionStoreEntry`. From `claude_agent_sdk.testing`: `run_session_store_conformance`.
- CLI protocol: the mirroring stream is requested with `--session-mirror`, resume uses `--resume` and `--continue`, and the configuration directory is `CLAUDE_CONFIG_DIR`. `MirrorErrorMessage.subtype == "mirror_error"`.
- `ClaudeAgentOptions.session_store` defaults to `None`; `ClaudeAgentOptions.load_timeout_ms` defaults to `60_000`.
